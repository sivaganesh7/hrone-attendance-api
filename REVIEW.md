# REVIEW.md

List every defect you found in the starter `app/main.py` (helpers and endpoints). For each one:

| # | Where (function / line) | What is wrong | How you'd notice it (test, input, or symptom) | How you fixed it |
|---|---|---|---|---|
| 1 | `compute_late_minutes` (lines 33–37) | Replaced hours/minutes on `punch_in` without accounting for IST vs UTC timezone offset; integer comparison `minutes > 10` causes punch-in at 09:40:01 (601s) to evaluate `10 > 10` (`False`), yielding 0 instead of 10; did not truncate instants to whole seconds first. | Punching in at 09:40:01 for a 09:30 shift returned `late_minutes: 0` instead of `10`. | Anchored shift start in IST on the derived attendance date, converted to UTC, evaluated `elapsed_seconds > 600`, and returned whole minutes floor `elapsed_seconds // 60`. |
| 2 | `compute_work_hours` (lines 40–41) | Used Python's built-in `round(..., 2)` which applies banker's rounding (round-half-to-even) instead of R4/R8 half-up rounding; did not truncate punch instants to whole seconds. | An elapsed work duration with `.xx5` fractional hours (e.g. 2.345) rounded down to `2.34` rather than up to `2.35`. | Implemented `round_half_up` helper using `decimal.Decimal` with `ROUND_HALF_UP` over whole-second truncated elapsed seconds. |
| 3 | `compute_overtime` (lines 44–47) | Counted overtime for any minutes $> 0$ rather than enforcing the R3 $\ge 30$ minutes threshold; overnight shifts (`shift_end <= shift_start`) anchored `shift_end` to `date_str` instead of `date_str + 1 day`. | Punch-out 5 minutes after shift end returned 5 minutes overtime instead of 0; overnight shift end fell on same day resulting in invalid calculations. | Added overnight shift detection advancing `shift_end` by 1 day when `shift_end <= shift_start`, and returned `minutes` only when `minutes >= 30`, else 0. |
| 4 | `get_attendance_date` (lines 30–31) | Derived attendance date purely from `punch_in.strftime("%Y-%m-%d")` without handling overnight shifts (R1) or timezone conversion. | Punch-in at 01:10 IST for a 22:00–06:00 overnight shift was assigned to that day rather than the previous calendar day when the shift began. | Implemented R1 overnight shift logic: if `shift_end <= shift_start` and punch-in time in IST is earlier than `shift_end`, date is previous day (`punch_in_ist - 1 day`). |
| 5 | `health` (lines 72–74) | Hardcoded `{"status": "ok"}` without pinging MongoDB, violating the readiness probe contract (must return 200 only if MongoDB answers a ping, else 503). | Stopping or disconnecting MongoDB still resulted in `GET /health` returning 200 OK. | Wrapped `client.admin.command("ping")` in a `try...except` block, raising `HTTPException(503, "Database unavailable")` on connection failure. |
| 6 | `create_employee` (lines 77–86) | Check-then-insert race condition allowed duplicate `emp_code` under concurrent requests; missing validation for `emp_code` regex (`^EMP\d{4,6}$`), email format, and `shift_start != shift_end`; stored and returned naive datetime `created_at` instead of epoch milliseconds. | Concurrent identical POSTs created duplicate employees; invalid codes like `"EMP1"` or equal shift times succeeded; response returned datetime string rather than integer epoch ms. | Backed `emp_code` with a unique index, caught `DuplicateKeyError` to return 409; added strict `EmployeeCreate` Pydantic model with regexes and validators; serialized `created_at` to epoch ms. |
| 7 | `list_employees` (lines 88–96) | Off-by-one pagination bug `skip = page * page_size` skipped the first page of results (`page=1` skipped 20 items); missing sort by `emp_code` ascending; `total` counted the whole collection ignoring filters; missing pagination parameter bounds validation. | Requesting `page=1&page_size=20` returned items 21–40; `total` reflected unfiltered count when `department` filter was applied; items returned in arbitrary order. | Changed skip to `(page - 1) * page_size`, added `.sort("emp_code", 1)`, scoped `count_documents` to query filter `q`, added `ge=1, le=100` bounds, and serialized `created_at` to epoch ms. |
| 8 | `punch_in` (lines 99–122) | Check-then-insert race condition on `(emp_code, date)`; unhandled 404 when employee does not exist (crashed with 500 `TypeError`); local timezone date calculation failed to handle overnight shifts in IST; accepted invalid statuses like `ABSENT` with 201; returned unauthorized `"id"` field and raw datetimes. | Missing employee caused 500; concurrent punch-ins created duplicates; overnight shift punches on next morning assigned wrong date; passing seconds timestamps or `ABSENT` status was accepted. | Verified employee existence (raising 404); resolved IST date with overnight shift logic; enforced unique compound index `(emp_code, date)` catching `DuplicateKeyError` (409); enforced `PunchInRequest` schema (422); serialized response without `"id"`. |
| 9 | `list_attendance` (lines 124–151) | Memory exhaustion vulnerability from loading full collection via `list(db.attendance_logs.find(q))` and sorting in Python; missing secondary sort by `emp_code` ascending; missing validation for `date_from > date_to` (must return 422); injected unauthorized `"id"` field. | Querying 100k records caused server memory blowout/hang; passing inverted dates `date_from > date_to` returned 200 with empty list instead of 422; records contained non-contract `"id"`. | Replaced in-memory sorting with database-side `.sort([("date", -1), ("emp_code", 1)]).skip(skip).limit(page_size)`; added validation raising 422 if `date_from > date_to`; properly formatted epoch ms fields. |
| 10 | Client setup & Indexes (lines 20–28) | `MongoClient` initialized without `tz_aware=True`; no indexes created at application startup, leaving queries to perform full collection scans (`COLLSCAN`) and leaving unique constraints unenforced. | PyMongo returned naive datetimes causing timezone conversion errors; explain plans contained `COLLSCAN`; concurrent inserts violated uniqueness. | Configured `tz_aware=True` on `MongoClient`; implemented idempotent `ensure_indexes` with pre-flight duplicate checks in FastAPI `lifespan` hook. |
| 11 | Instant validation (schemas) | Accepted seconds-looking integers (< 100000000000), floats, strings, and booleans without validation errors. | Passing `punched_at: 1783310280` (seconds) was accepted instead of rejected with 422. | Introduced `EpochMillisField` with `strict=True`, `ge=100000000000`, `le=4102444800000`. |
| 12 | R1 whole-second truncation | Instant calculations and storage included milliseconds and microseconds, violating R1 rule that instants must be truncated to whole seconds. | Punching in at `09:40:00.900` counted fractional seconds, causing inconsistent lateness and work-hour calculations. | Truncated all incoming and server clock instants with `microsecond=0` and integer division `ms // 1000 * 1000` before persistence and calculations. |

## Items Examined and Found Correct

1. **IST Timezone Definition (`IST = timezone(timedelta(hours=5, minutes=30))`):**
   Correctly defines Indian Standard Time as UTC+05:30.
2. **Identification by Composite Key `(emp_code, date)`:**
   Correctly adheres to the specification where attendance records have no separate ID field or exposed MongoDB `_id` in requests or responses.
3. **Read-only Derived Fields:**
   `work_hours`, `late_minutes`, `overtime_minutes`, and `half_day` are excluded from request bodies and only computed by the API.
4. **Pagination Default and 1-based Indexing:**
   `page` starting at 1 and default `page_size = 20` correctly align with rule R10.
5. **Standard Error Schema Structure:**
   FastAPI default error response shape `{"detail": ...}` exactly satisfies OpenAPI's `#/components/responses/Error` and `#/components/responses/ValidationError`.
6. **Audit Trail Scope during Punch-in:**
   `history` is reserved solely for manual corrections (PATCH regularization); punch-in correctly initializes `history: []` without recording entries.
7. **Presence Status Coverage:**
   Punch-in accepts only `PRESENT`, `WFH`, and `ON_DUTY` (per R6), rejecting non-presence statuses like `ABSENT` or `LEAVE` at the schema boundary.
